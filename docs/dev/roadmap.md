# 插件接下来怎么走

五个插件，各做一件事，分开安装。这份文档只回答两句：先做哪几件，哪些先别做。

依据是 2026-10-19 的仓库。验证基线是官方 `0.2.1-rc.2`（`compatibility/policy.json`）。不写发布日期。

## 先看这五步

```text
1 改说错的说明
      ↓
2 让 Delegate 的失败和取消有测试
      ↓
3 让 Code 失败时不要显示成「没发现问题」
      ↓
4 用真桌面验一次 Browser          5 决定要不要买 A 股授权源
   （不过也算有记录）                 （不决定就不写适配器）
```

1、2、3 不需要桌面环境，也不需要付费账号，按这个顺序做。4 和 5 互不阻挡，但都要等你拍板。

| 步 | 做完能确认什么 | 先别碰 |
| --- | --- | --- |
| 1. 改说明 | 读文档的人不会按错误边界去改代码 | 不改行为 |
| 2. Delegate 测试 | 启动失败、空结果、崩溃、取消，都有终态，不留进程 | 不接真 CLI、不打包二进制 |
| 3. Code 测试 | 审批后源码或模型变了、回答被截断、模型要调工具、用户取消，都记成失败 | 不加修复按钮 |
| 4. Browser 真机 | 当前这个包在打包后的 Desktop 上，观察和点击是通还是不通 | 不加新动作 |
| 5. 授权源决定 | 要么选定一家并写清许可，要么写明「这阶段不接」 | 不先做「通用授权入口」 |

## 五个插件现在是什么

| 插件 | 现在能用来做什么 | 不要把它说成 |
| --- | --- | --- |
| Code | 看本地 Git，把选中的一小段快照交给**当前这个 DSH 模型**审。改代码仍在主对话里做，改完对同一批文件再审一次 | 会自己改代码、跑测试、提 PR |
| Browser | 桌面侧边栏里开一个网页。模型只能观察、打开、点击、输入、滚动、按键、后退、前进、刷新，而且每一轮要重新允许 | 已经在打包应用里验过。本仓库的测试用的是假 webview |
| Stock | 自选、固定栏、市场全景、日 K。A 股默认没有数据源。打开「免费源」才走腾讯公开接口。旁边的报价工具只打 Finnhub，要自己的 key | 能交易，或免费源是交易所授权行情 |
| Delegate | 把一段自包含任务交给本机已经装好的 Codex、Grok 或 OpenCode | 插件自带这些程序。也不是只读：Grok/OpenCode 默认只读，Codex 默认可写工作区 |
| Pet | 窗口右下角放一只与 Codex 同规格的桌宠，只改外观 | 会操作文件、审批或会话；会自带素材 |

## 第 1 步：三处说明和代码不一致

只改说明，不改行为。这三处会让下一步改错地方。

1. **Delegate 的权限。** `packages/dsh-x-delegate/VALIDATION.md` 把默认写成只读。代码里只有 Grok/OpenCode 默认 `read-only`；Codex 在 `packages/dsh-x-delegate/src/index.ts` 和 `cordis.patch.yml` 里默认 `workspace-write`。另外 `README.md` 写了 `command: bundled`，但 `resolveCodexCommand` 没有被启动路径调用，不要当成已经能用。
2. **Stock 只有一个 A 股开关。** `packages/dsh-x-finance/README.md` 第 98 行说 `marketSource` 和 `freeSource` 各管一路。`packages/dsh-x-finance/src/index.ts` 里两者打开的是同一个源，`freeSource` 是旧名字。Finnhub 工具仍然分开，不要并进去。
3. **插件数量只认一份清单。** 现在是五个包，`packages/README.md` 与 `compatibility/policy.json` 是来源；`docs/` 不要再出现三个或四个的旧口径。

做完的样子：这三处和上表一致，没有顺手改功能。

## 第 2 步：Delegate 先补「出事以后怎样」

现在 `packages/dsh-x-delegate/test/wire.test.ts` 只测了协议折叠，没有测一次完整的启动和退出。

用官方的 activation，配一个假子进程，覆盖这四种：

- 命令找不到，或握手失败
- 跑完了但没有答案
- 进程异常退出
- 提问过程中取消

做完的样子：每种都是失败，不是成功；取消后不留进程，也不把同一结果送两次。不要自动换另一家代理再跑一遍，因为子进程可能已经改过工作区。

## 第 3 步：Code 的失败不要看起来像「干净」

审查主路径已经有测试。缺的是这几种必须失败、而且界面不能显示成「未发现问题」：

- 用户拒绝审批（此时还不能把源码发出去）
- 审批过程中，源码或模型变了
- 回答被截断、超长，或者模型反过来要求调工具
- 用户取消

范围也写成测例，不要只写在 README 里：最多 20 个文件、前后文合计 48 KiB、提示最多 64,000 字。超出就拒绝，不要悄悄截短再审。

修代码、跑测试、提交，继续留在主对话。不要把已经删掉的 `dsh_x_code_repair` 加回来。

## 第 4 步和第 5 步：等决定，再动手

**Browser。** 先定验证记录放在本库还是应用仓库。然后用当前这版官方打包 Desktop 跑一遍：打开网页、观察、点击、接管、关掉标签。跑失败也留下记录（哪一版、哪个系统、哪一步失败）。没有这份记录之前，保持实验、默认不装。

CDP 控制面已经定案，见[浏览器走 CDP 怎么落地](browser-cdp.md)：引擎用 `agent-browser`，模型仍然拿不到 JavaScript、选择器或 CDP 命令。真机记录仍然是发布前的门槛，不因为换了引擎就跳过。

**Stock。** 先决定要不要接一家有许可的 A 股源（市场、字段、费用、能不能展示）。决定「不接」也是完成。决定「接」之后，只加这一个受信适配器，密钥留在宿主，失败时不要悄悄退回腾讯源。基本面、下单、持仓都不在这一步。

## 做完 1–3 之后，每个插件只加这一件

| 插件 | 下一件值得做的 | 做完是什么样 |
| --- | --- | --- |
| Code | 重审时把「当前文件」和「上次审的快照」分清 | 空的重审只表示这一次没发现，不表示测试通过，也不把旧问题自动勾掉 |
| Browser | 现有动作在真网页上的进退和多标签 | 换页之后旧授权失效；两个标签不会串 |
| Stock | 适配器返回的字段收干净，取消订阅后旧包不再刷界面 | 多出来的字段进不了页面；关掉免费源就不再请求 |
| Delegate | 调用前能看见这次实际用的模型和权限 | 看得到「配置如此」还是「刚探测过」；探测本身不登录、不安装 |

## 一直不要做

- 不把官方内核放进这个仓库，也不给内核打补丁。
- 不做桌面安装包，不发布 npm。五个包各自有 version，仍用一个 `plugins-v*` tag 发布索引。
- 不用独立的 `~/.dsh-x`，不动官方 `sessions/`。
- Code 不执行测试、不写 PR、不内置另一套编程代理。
- Browser 不把页面脚本或 CDP 命令交给模型执行；CDP 只是内部传输。不绕过沙箱、下载限制和登录框。
- Stock 不交易，不把免费源说成授权行情，也不在失败时偷偷换源。
- Delegate 不把 Codex、Grok、OpenCode 打进发布包，也不替用户登录。

## 还没定的，只有这两件

| 要你决定 | 没决定时 |
| --- | --- |
| A 股授权源接不接，接哪家，许可允许做什么 | 继续「默认没源，免费源要手动打开」 |
| Browser 的桌面验证记录记在哪个仓库、谁更新 | 继续标实验，默认不安装 |

内核升级不跟这五步绑在一起。官方 API 变了，按 `docs/dev/release.md` 单独重跑，不要因为 peer 范围写着还能装，就当成已经验过。
